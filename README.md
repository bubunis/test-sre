# Token Issuance Service

A small token service with built-in OpenTelemetry observability (metrics, logs,
traces). A Python API checks the user's permissions in PostgreSQL and asks a Go
gRPC service to mint a short-lived token, which is stored in Redis.

> **Status:** being hardened for production, one step at a time. Docker only:
> no cloud, no Kubernetes. Steps 1–3 are in place: secrets, closed ports,
> token lifetime cap, and JWT authentication for callers. Progress, tests and
> open items are tracked in [`docs/SECURITY-HARDENING.md`](docs/SECURITY-HARDENING.md).

## Architecture

```text
                     only :8000 is published
Calling service ──(Bearer JWT)──► Python API (FastAPI) :8000 ──► PostgreSQL
                                        │                         (password from secret file)
                                        │ gRPC
                                        ▼
                                  Go token service ──► Redis
                                                       (password required)

Telemetry: both services ──OTLP──► OTel collector ──► Jaeger
           Prometheus scrapes both services
Jaeger UI 127.0.0.1:16686 and Prometheus UI 127.0.0.1:9091 (this machine only)
```

**Python API** (port 8000): `POST /token` checks the caller's JWT, then looks
up the user's permissions in PostgreSQL. If the user exists, it asks the Go
service to mint a token. It also serves `/health` and `/metrics`.

**Go token service** (gRPC 50051, metrics 9090, both internal only): generates
a random 256-bit token and stores it in Redis with an expiry decided by the
server.

## Security

| Control | What it means |
| --- | --- |
| No hardcoded passwords | Postgres and Redis passwords are random, generated by `scripts/init-secrets.sh` into `secrets/` (never committed). Containers read them as Docker secrets from `/run/secrets/...`. |
| Only the API is published | Postgres, Redis, gRPC, Go metrics and the OTel collector are reachable only inside Docker. The Jaeger and Prometheus UIs are bound to `127.0.0.1`. |
| Redis requires a password | Set through a mounted config file, so the password never appears in process listings. |
| Tokens always expire | The server decides the lifetime: `ttl_seconds = 0` → 15 minutes; 60–3600 s → as requested; anything else is refused with `InvalidArgument`. |
| Callers must authenticate | `POST /token` requires `Authorization: Bearer <JWT>`: a valid signature (asymmetric algorithms only), the right issuer and audience, not expired, and the `token:mint` scope. Missing or invalid → `401`; wrong scope → `403`. |
| Fail closed | The API refuses to start if its database password file or JWT settings are missing. There is no switch that turns authentication off. |

**Known gaps** (planned, see the hardening log): containers still run as root;
the API still uses the Postgres superuser; traffic between containers is not
encrypted yet; any container on the Docker network can call the Go service
directly; a caller with a valid JWT can request a token for any existing user
(per-client grants come later).

## Quick start

**Requirements:** Docker with Compose v2, `openssl`, and [`uv`](https://docs.astral.sh/uv/) (only for running the Python tests).

```bash
# 1. Create local secrets: DB and Redis passwords plus a DEV-only JWT key pair
bash scripts/init-secrets.sh

# 2. Build and start everything
docker compose up -d --build
docker compose ps                     # all services "Up"

# 3. Get a dev JWT (signed with the dev private key) and request a token
JWT=$(bash scripts/dev-token.sh)
curl -s -X POST http://localhost:8000/token \
  -H "Authorization: Bearer $JWT" \
  -H "Content-Type: application/json" \
  -d '{"user_email": "alice@example.com"}'
# → {"token": "...", "permissions": ["read:data", "write:data"]}
```

`init-secrets.sh` is safe to re-run: it never overwrites existing passwords or
keys. If you change the Postgres password after the database was first
created, start again with `docker compose down -v`, because Postgres sets its
password only on first start.

### Dev tokens

`scripts/dev-token.sh [client_id] [scope] [ttl_seconds]` prints a signed test
token. It runs in a throwaway `python-service` container with the private key
mounted read-only, so the key never goes into an image.

```bash
bash scripts/dev-token.sh                                  # valid: login-service, token:mint, 5 min
bash scripts/dev-token.sh login-service profile            # wrong scope    → API returns 403
bash scripts/dev-token.sh login-service token:mint -120    # expired 2 min ago → API returns 401
```

The API allows 30 seconds of clock skew (`JWT_LEEWAY_SECONDS`), so a token
that expired less than 30 seconds ago is still accepted.

The dev key pair stands in for an identity provider. **Never use it in
production** (see [Production configuration](#production-configuration)).

## API

| Method | Path | Auth | Response |
| --- | --- | --- | --- |
| `POST` | `/token` | Bearer JWT with scope `token:mint` | `200` token and permissions · `401` no or invalid JWT · `403` missing scope · `404` user not found |
| `GET` | `/health` | none | `{"status": "healthy"}` |
| `GET` | `/metrics` | none | Prometheus metrics for the API |

Request body for `/token`: `{"user_email": "alice@example.com"}`.

## Observability

| Type | Python API | Go service |
| --- | --- | --- |
| **Metrics** | `http://localhost:8000/metrics` | Internal only: `docker compose exec golang-service wget -qO- http://localhost:9090/metrics` |
| **Logs** | OTLP export with trace correlation | OTLP export with trace correlation |
| **Tracing** | Auto-instrumented (FastAPI, gRPC, psycopg2) | Auto-instrumented (gRPC, Redis) |

* Jaeger UI: <http://127.0.0.1:16686>
* Prometheus UI: <http://127.0.0.1:9091>
* Go metrics include `tokens_minted_total{status="success|error|rejected"}` and `token_mint_duration_seconds`.

Traces are correlated across services with W3C TraceContext. When
`OTEL_EXPORTER_OTLP_ENDPOINT` is set, traces and logs are exported over OTLP.

## Configuration

### Python API

| Variable | Required | Description |
| --- | --- | --- |
| `DATABASE_URL` | yes | PostgreSQL URL **without** a password, e.g. `postgres://postgres@postgres:5432/tokendb` |
| `DB_PASSWORD_FILE` | yes | File holding the database password (Docker secret) |
| `TOKEN_SERVICE_HOST` | no | Go gRPC address (default `localhost:50051`) |
| `JWT_ISSUER` | yes | Expected `iss` claim |
| `JWT_AUDIENCE` | yes | Expected `aud` claim |
| `JWT_JWKS_URL` | one of these two | HTTPS URL of the identity provider's signing keys (production) |
| `JWT_PUBLIC_KEY_FILE` | one of these two | PEM public key file (dev and CI) |
| `JWT_ALGORITHMS` | no | Allowed algorithms, comma-separated (default `RS256,ES256`; asymmetric only) |
| `JWT_REQUIRED_SCOPE` | no | Scope a caller must have (default `token:mint`) |
| `JWT_LEEWAY_SECONDS` | no | Allowed clock skew (default `30`) |
| `JWT_CA_FILE` | no | CA bundle for the JWKS HTTPS connection (internal CA) |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | no | OpenTelemetry collector endpoint |

### Go token service

| Variable | Required | Description |
| --- | --- | --- |
| `REDIS_ADDR` | no | Redis address (default `localhost:6379`) |
| `REDIS_PASSWORD_FILE` | yes in Docker | File holding the Redis password (Docker secret); the service exits if it can't read it |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | no | OpenTelemetry collector endpoint |

Token lifetime limits are fixed in code (`golang-service/internal/tokenpolicy`):
default 15 minutes, minimum 1 minute, maximum 1 hour.

### Production configuration

Replace the dev key with your identity provider's keys:

```bash
JWT_ISSUER=https://idp.internal/realms/platform
JWT_AUDIENCE=token-service
JWT_JWKS_URL=https://idp.internal/realms/platform/protocol/openid-connect/certs
JWT_ALGORITHMS=RS256
JWT_CA_FILE=/run/secrets/ca_crt          # if the IdP uses an internal CA
# and remove JWT_PUBLIC_KEY_FILE
```

Calling services get tokens through the OAuth2 client-credentials flow. The
client ID comes from the token's `azp` claim, or else `client_id`, or else `sub`.

## Testing

```bash
# Go unit tests (token lifetime rules)
cd golang-service && go test ./... && cd ..

# Python unit tests (JWT checks: expiry, audience, issuer, alg=none,
# HS256 key confusion, wrong key, scope, fail-closed config)
cd python-service && uv run pytest -q tests && cd ..
```

**CI** (`.github/workflows/ci.yml`) runs on every push and pull request to `main`:

1. **Build & Validate:** Go unit tests, Python unit tests, `docker compose build`.
2. **Observability Contracts:** the API's `/health` and the Go `/metrics` endpoint respond.
3. **Stateful E2E Flow:** requests without a valid JWT get 401/403; a valid
   JWT gets a token for alice with the right permissions; the token is stored in Redis.

## Developers

If you change `protos/token.proto`, regenerate and commit the generated code.

**Python:**

```bash
cd python-service
uv run python -m grpc_tools.protoc -I../protos --python_out=. \
  --grpc_python_out=. ../protos/token.proto
```

**Go:**

```bash
cd golang-service
go install google.golang.org/protobuf/cmd/protoc-gen-go@latest
go install google.golang.org/grpc/cmd/protoc-gen-go-grpc@latest
protoc -I../protos --go_out=proto --go-grpc_out=proto \
  --go_opt=module=token-service/proto \
  --go-grpc_opt=module=token-service/proto \
  ../protos/token.proto
```

**Rules for changes:**

* Never commit anything under `secrets/`. Check `git status` before each commit.
* Start each change from an up-to-date `main` (`git checkout main && git pull`), one branch per change.
* Record security-relevant changes and their test results in `docs/SECURITY-HARDENING.md`.
